# Working Preferences

## Coding Standards and Conventions

### Java Standards
- Follow **standard Java conventions** for code style and structure
- Maintain consistency with existing codebase patterns
- Prioritize code clarity and maintainability

### Documentation
- Prefer **clear documentation** that explains intent and usage
- Document public APIs thoroughly
- Include examples where appropriate
- Keep documentation up-to-date with code changes

### Testing
- Maintain **comprehensive tests** for all features
- Write tests that are clear and maintainable
- Ensure tests cover edge cases and error conditions
- Test across supported CDI runtimes when applicable

## Development Approach

### Change Management
- Follow standard Java conventions throughout the codebase
- Ensure changes maintain backward compatibility where possible
- Consider impact on multiple CDI runtime implementations

### Code Quality
- Focus on **maintainability and code clarity**
- Write self-documenting code with clear naming
- Avoid unnecessary complexity
- Refactor when patterns emerge

## Communication Preferences

### Commit Messages
- Write clear, descriptive commit messages
- Follow conventional commit format when appropriate
- Reference issues or features being addressed

### Code Reviews
- Value constructive feedback
- Focus on code quality and maintainability
- Consider multiple perspectives and approaches

## Working with AI Assistants

### Collaboration Style
- **Explain reasoning**: Provide context and rationale for suggestions
- **Suggest alternatives when relevant**: Offer different approaches when appropriate
- **Consider full project context**: Take into account the broader codebase and architecture

### Context Awareness
- Understand the CDI integration patterns used in the project
- Be aware of portable extension mechanisms
- Consider compatibility across different runtimes
- Reference existing patterns and conventions in the codebase

### Best Practices
- Balance explanation with action based on task complexity
- Provide complete, working solutions
- Consider edge cases and error handling
- Suggest improvements when opportunities arise
- Respect the project's focus on developer experience

### What to Avoid
- Don't make assumptions without checking the codebase
- Don't introduce breaking changes without discussion
- Don't ignore existing patterns and conventions
- Don't provide partial or incomplete solutions
